# Design

## Context

See proposal.md for motivation and capability boundaries. The backend is Fastify/Bun with SQLite/Drizzle; the Vue frontend already has MarkdownContent, native paper/PDF anchors, Semantic Scholar resolution/import and user-specific tags. `/mcp` resolves personal/agent credentials to actual users; Q&A agents already use the requesting user's identity. `/research` currently starts site-run Codex rounds. Preserve the independently edited migration, backup and Q&A feed work and all existing Research data.

The user confirmed one main report, a hierarchical list, Semantic Scholar external entries with explicit one-click import, replacing the original Deep Research entry, Topic-and-user credentials for MCP/Git, and token-independent per-tool counts. They deferred per-request traffic tables. Subsequent approved page/catalog and general-access decisions below supersede the initial reading structure.

## Goals / Non-Goals

**Goals:** one authoritative Git version per published Topic; identical ACLs for web, history, MCP and Git; portable persistent storage; recoverable publication; conservative pure-addition animations; offline regression tests.

**Non-Goals:** general Wiki engines, browser report editing, branch/PR UI, automatic discovery or reference refresh, anonymous Topic sharing, ongoing Research synchronization, and byte-volume traffic reporting. Legacy Research remains available through history; Topics becomes the primary research entry.

## Decisions

### Repository contract

Use one bare repository per Topic under configurable `topics.repos_dir`, default `./data/topics`. Use numeric database Topic identity for server storage; keep the file format independent of deployment paths.

- `topic.json`: `{ "format_version": 1, "title": "...", "description": "..." }`.
- `report.md`: one UTF-8 Markdown document; an initialized empty report is allowed so newly created Topics are immediately clonable.
- `papers.json`: `{ "format_version": 1, "directories": [{ "id": "stable-id", "name": "...", "parent_id": null }], "papers": [{ "id": "stable-entry-id", "title": "...", "paper_id": 123, "directory_ids": ["stable-id"], "comment": "..." }] }`. An external entry uses `s2_id` instead of `paper_id`, normalized with the existing S2 identifier rules. `directory_ids: []` means the Topic root; an entry can occupy several directories. Preserve array order. Reserve `root` for the generated root node and reject duplicate IDs/cycles/dangling parents or directory references.
- An optional README.md documents maintenance and credential use. The original v1 accepted only these root text files; the approved extension below also accepts bounded pages/*.md documents. Continue to reject executable modes, symlinks, submodules and other paths. The extension preserves existing format-version-1 files and histories.

Display metadata is committed with entries so an external reference remains readable offline. Push validation performs no S2/model requests and does not ingest papers. Explicit import uses existing paper ingestion/deduplication and adds the paper to the acting reader's library. Current association rows can resolve a committed S2 ID to a subsequently imported site paper; this is metadata enrichment, not a report/list revision. Readers may import into their own libraries without editing the shared Git content. Preserve historical list structure while showing current availability of native paper links.

### Git transport and consistent publication

Expose smart HTTP at `/topic-git/:id.git/info/refs` and upload/receive-pack endpoints, using native Git subprocesses. Both Git reads and writes require that user's Topic token (HTTP Basic with token as password, or Bearer); cookie and personal credentials do not authorize Git transport. Never put secrets in URLs. There is no per-repository resident process.

Serialize mutations per Topic. For a push, create a temporary bare staging clone using local object sharing and run stateless receive-pack there with bounded input, time and output. Buffer its protocol response until final publication. Disable hooks and automatic maintenance for controlled subprocesses; no client files are executed. Ref checks allow only a non-deleted main ref with an ancestor-preserving update. Validate every introduced commit, not just its tip, including local paper-ID existence and content limits. Reject invalid staged pushes with a diagnostic and leave the real repository untouched.

For a valid staged result: recheck the credential/ACL, durably prepare a journal containing old/new commits, authenticated user/token ID, server time and validated revision metadata; transfer objects locally without changing main; compare-and-swap main; transactionally update commit metadata, push audit, the complete current snapshot and generated associations; then return Git's successful protocol response. This staging boundary avoids acknowledging or exposing invalid refs. Clean temporary clones after each operation.

Git and SQLite cannot share one atomic commit. Keep a durable publication journal before the ref update and a complete prior readable snapshot in SQLite. Before Git access, before another mutation and at startup, reconcile any advanced main with its prepared journal and idempotently finish indexing/audit. If indexing fails, fail the push HTTP request, keep the previous complete website snapshot, and retry recovery; do not return a successful push. Historical API reads are restricted to commits reachable from the published version. Block Git reads when reconciliation cannot complete so an unindexed update is not advertised as published. Do not rewrite main automatically to hide a synchronization failure.

### Persistence

Use additive Drizzle migrations:

- `topics`: owner, current title/description, published commit, complete current snapshot and timestamps.
- `topic_members`: Topic/user key, viewer/editor/owner role, active flag, and `mcp_call_counts` JSON. Retain removed individual grants' counters while applying the current general access policy.
- `topic_versions`: Topic/commit key, parent, declared Git author/committer metadata, message/time and associated push. Historical content is read from Git rather than copied into a second full history store.
- `topic_pushes`: original authenticated uploader, optional credential identifier, old/new commit and server time, with idempotent publication identity.
- `topic_nodes` and `topic_papers`: latest source-aware node/ancestor/entry associations, with nullable native paper binding and normalized external S2 identity. Paper deletion clears bindings safely. These are rebuildable from current snapshots.
- `api_tokens.topic_id`, kind `topic`, and `users.mcp_call_counts`. Store only a namespaced hash verifier for newly issued Topic secrets in the existing token column; retain existing personal/agent values and lookups.

No dedicated traffic table. Each authenticated known-tool attempt updates user per-tool counts and optional Topic-member counts atomically, before invocation; failures still count. Protocol messages do not count. Site-run agents, including Q&A's image tool, go through the same dispatch instrumentation. Missing map keys read as zero; no historical backfill. Provide a caller-only aggregate read endpoint and include the caller's Topic subtotal in Topic metadata, without another member's global activity. Credential rotation never changes counter identity.

### Authorization and API boundaries

Centralize Topic access checks without a site-administrator bypass. Per-Topic default_access is none (Private), viewer or editor (Public to active signed-in accounts only). Owner identity always wins; effective role is the higher of the active explicit grant and the general default (none < viewer < editor); removed/inactive grants fall back to the default. Rows retained only for public-user counters use role=default and follow policy rather than becoming explicit grants. Listing, generated badges, history, MCP and Git use the same effective-role rule. Existing Topics default to none, retaining every explicit membership. No global sharing setting controls Topics. Owner-only policy and membership changes, serialized with pushes; changing policy does not rewrite Git history. Public-to-private denies default users immediately; existing explicit grants remain. Removing an individual grant restores general access; it cannot restrict a user below the general policy. New Topic creation accepts default_access (omission is private), exposed by browser and personal-token MCP create; Share offers the same three choices. Other account-wide sharing settings continue to apply only to their original data types.

Owner-only membership changes; active members issue/revoke/rotate their own scoped credentials. Revocation/downgrade and push publication use the same per-Topic serialization. Every request rechecks current account status and membership rather than trusting stored token privileges.

Topic tokens carry actual user plus bound Topic in MCP context. They expose bound-Topic reads/history/instructions and safe shared-paper research tools. They do not create other Topics, change memberships, issue credentials, invoke generic paper mutation tools, or read private user tags/Q&A. Dedicated entry import only imports an entry already in the bound Topic into that user's own library. Personal tokens may create/manage Topics within membership authority. Existing site-run agent tool allowlists remain unchanged; new Topic mutation tools are not enabled in legacy automatic rounds.

Use browser `/api/topics` endpoints for create/list/detail/history, members, own credentials, explicit imports and a validated source-result seed. MCP wraps the same services. Keep all request/response/manifest keys snake_case. Counts are grouped by known tool name, actual user and optional authenticated Topic context, not by an arbitrary client-provided Topic parameter.

### Generated tags and paper filtering

Keep personal tags and paper_tags untouched. Return separate `topic_tags` root badges with Topic/node identity; fetch hierarchy only for accessible Topics. The Topic and stable node IDs form generated-tag identity, so renaming/moving does not merge tags by name. Build ancestor associations for each entry; imported paper bindings make them available in normal search. Root badges appear in paper list/detail outside the manual-tag editor. `topic_id`/`topic_node_id` filters combine with existing search, tags and scope. Badge navigation uses all-paper scope so a shared Topic is not unexpectedly hidden by the reader's personal library. History never rewrites the latest index.

### Frontend entry, reading and last-seen cache

Use `/research` for the Topics AppPage and alias `/topics`; use `/topics/:id` for Topic details. Move legacy ResearchList to `/research/history`, preserve `/research/:id` for existing detail links, and adjust back/history and completion links accordingly. Change the Q&A result action to Create Topic, seeding the initial report from an authorized copied question/answer snapshot without starting a model. The history list does not become the primary new-session entry.

Topic detail presents Report, Papers, History and owner/member connection controls, with usable layouts on phone and desktop. Reuse MarkdownContent with private highlight editing disabled and existing paper/PDF navigation. The paper tree provides directory navigation, external S2 links and one-click import; history selectors identify declared authors separately from real pushers.

Store a versioned cache keyed by account and Topic latest-view page. It contains the last actually rendered report/list and commit, not merely a commit hash. Compare stable entry/directory identities and Markdown parser block tokens against that baseline. Use sequence diff anchors: only runs inserted without replacing old blocks are additions; modifications/deletions stay static. If no usable baseline or the document is wholly new, animate nothing. Apply all addition classes on one render frame, respect reduced motion, then save the displayed snapshot after rendering. Ignore historical browsing for the latest baseline; catch storage errors and prevent a stale async response or account switch from saving the wrong cache. Do not split Markdown in ways that break references or formulas.

### PDF page MCP

Add `read_pdf_page(paper_id, page, image?, region?, offset?, max_chars?)`. Use the existing local PDF path only after confinement checks. Physical pages are 1-based. Use configurable local Poppler executables (`pdfinfo`, `pdftotext`, `pdftoppm`) for bounded selected-page text/rendering; no model calls or remote fetching. Limit concurrent processes, runtime, raster dimensions and output bytes. Return text chunks with page metadata, next offset and a complete native Markdown citation. Only `image: true` creates the selected page PNG and an MCP image content block. An optional valid rectangle affects the native region citation; the screenshot remains the full page. Preserve text-only callAgentTool callers while permitting rich image blocks at the MCP boundary.

### Configuration and operational approach

Add validated `topics` and `pdf_pages` blocks with defaults for storage/executables/time/size/concurrency limits. Default Topic storage resides under the existing persistent data directory; allow absolute paths for portability. Ignore runtime repos/staging/journals in source control. Document all persistent directories and recovery prerequisites without taking over the parallel backup project. Do not bump the application version before archive.

### One-time legacy Research migration and web rename

The user subsequently requested actually migrating the old results and allowing shorter user-edited Topic names. The current source has 8 sessions and 24 result versions, with 735 S2 and 334 URL item occurrences. Each session becomes one Topic under the same owner; each valid result/title-edit version becomes one Git commit, with no extra empty initial version. Preserve reports exactly, section descriptions/comments, ordered URL citations, change notes and original source references. URL entries are preserved as clickable reference items (no automatic ingestion); this compatibility extension does not add any new collection mechanism. Extend directories with optional Markdown descriptions and entries with safe URL/citation fields and verification metadata.

Generate directory identities deterministically using exact title matching followed by positional rename matching across legacy versions; preserve occurrence-specific comments with stable per-section/item identities. S2 titles/authors/year come only from existing local paper/cache records, with identifier fallbacks, never remote lookups. Original conversations, raw answers, inputs and seeds remain intact in legacy tables and are linked from the imported Topic.

Add nullable unique legacy-session provenance and a pending/complete migration state on Topics, a transient persisted plan for resumable conversion, and unique legacy-step provenance on version metadata. Pending Topics are hidden/blocked across list, content, Git and generated tags until their entire history/memberships are complete. Persist the plan before repository writes; publication journals and per-step provenance allow reruns to finish interrupted work without duplicates. Completed imports are never replayed over later user edits. A CLI supports read-only dry run, explicit apply and verification, takes a consistent SQLite safety backup before writing, and writes a migration receipt. Execute it once with the service quiesced after checking active work, then restart and verify. Keep all source Research rows unchanged. Source-shared sessions grant current active accounts viewer memberships; private sessions stay owner-only, and general admin bypass is not converted into sharing.

System migration commits identify the migration actor with no invented authenticated Paperland uploader (system ID zero/null, explicit migration display name). Preserve source step/model/time in commit provenance. Normal web rename commits record the authenticated owner/editor. A reusable controlled server-side commit path uses the same journal/CAS/index transaction as Git publication. Rename carries the opened base commit, edits only topic.json, preserves the report/list/README blobs, and atomically refreshes the root tag name with stable Topic/directory IDs. The detail page offers English Edit name/Save/Cancel controls only for editors/owners reading latest; pause polling while editing and retain the typed name on conflicts.

### Latest approved reader and numbered-reference model

This decision supersedes the initial single-report/visible directory-tree design. Retain report.md as the main report and allow up to 32 optional pages/<safe-slug>.md documents. Left navigation selects documents and includes a dedicated Research questions page (pages/questions.md, initialized for new Topics; an English empty state for older Topics until real content is supplied), plus a global References view over papers.json. Main content uses a themed bg-card surface. Right sidebar shows only the selected document's reference subset; no global directory tree. Narrow screens use Files and References drawers. Report and all supplementary pages/catalog are validated/published at one Git commit, and history reads the same complete set. No browser report editing or general Wiki subsystem is added. The later v2 layout below supersedes root report.md, flat navigation and the central global-catalog view.

Each document may start with YAML frontmatter `references: [3, 8, 12]`. Strip that header only for presentation, retaining raw Git content. Require unique positive integer references that exist in that version's global catalog. A legacy main report lacking references displays all its catalog entries; supplementary pages without the field have an empty subset. Members can associate related or planned reading without placing every citation in prose. Relative links between known Markdown pages navigate within Topic/history. Legacy directories/comments/descriptions remain in the file format and historical data for preservation; new Topics use a flat catalog. Their existing derived filter associations remain compatible until a later user-requested content conversion; the new reading UI does not organize by them.

Use an additive append-only topic_references registry keyed by Topic/stable entry ID, with a unique positive reference_number per Topic, source identity and first commit/time. Publication prepares reference allocations in chronological introduced-commit order, checks optional declared reference_number values, validates document subsets, and includes allocations in the durable journal. New entries get the next unused number; removed numbers stay reserved and reappearing entries retain their number. A number/ID cannot be reassigned to a different source. Existing commits lacking explicit numbers remain valid; return authoritative number mappings and next_reference_number through web/MCP so agents can include numbers in papers.json and frontmatter. Allocation order follows first Topic appearance, never publication year or later array reorder. Deterministic first appearance is array order within a commit. Entry IDs remain canonical catalog identity; pages reuse the same entries rather than duplicate metadata. Legacy occurrence-specific IDs remain preserved by the generic upgrade. The separately authorized Topic 3 maintenance will use the user-provided RQ0-RQ7 decomposition and preserve useful source comments while rewriting the current wiki; original histories remain intact.

Before accepting traffic after the additive migration, backfill reference registries from existing published Git history in version sequence, without rewriting commits or original reports; a references_indexed_commit marker makes this resumable/idempotent. Recovery preserves prepared allocations and original uploader/time. Read historical catalog numbers only for entries present in that snapshot. Git-controlled rename preserves supplementary page blobs as well as main report/list/README. Limit accepted file count and aggregate text bytes as well as individual file size, and continue rejecting unsafe paths/modes and invalid intermediate commits.

Reading caches are isolated by account, Topic and selected document/reference surface. Hidden pages and unopened mobile drawers never advance their baselines. Each page's report body and visible reference list keep independent last-rendered content/commit; global References has its own list baseline. Simultaneous additions on currently displayed surfaces share a frame/time; first/all-new content, modifications, deletions and repeated displays stay static. Historical views do not advance latest baselines. New raw frontmatter metadata does not count as a rendered paragraph.

Share and Connect remain separate buttons/drawers. Share shows default access and explicit members, owner-only mutations; Connect contains only the caller's tokens, MCP/Git URLs, instructions and call counts. Creation chooses Private/Public and, for Public, Viewer/Editor, with Private the default. Public means active signed-in site accounts. Existing Topics keep prior grants; no global Research preference controls them.

### Latest follow-up: first-class pages, workspace and compact three-column reader

All published Markdown documents move to pages/, including the default pages/report.md. Root topic.json and references.json remain machine metadata (format1 papers.json remains readable in history); AGENTS.md is the explicit agent-guide exception, and README.md describes the repository rather than serving as a research page. Other safe regular files are an agent workspace: Git retains them but the website does not render or execute them. Workspace files share the Topic ACL and are included in Git reads/history, never a separate private area. Keep file/push/aggregate limits and reject unsafe paths, symlinks/submodules; executable mode is allowed only on auxiliary blobs, never published documents/metadata. Accept bounded binary workspace files without decoding them as report text. Research questions live in pages/research-questions/, and the pre-split Topic3 report remains a first-class page under pages/background/. Nested Markdown paths form the left file tree automatically, with folders collapsible and the active path revealed. title and fonticon frontmatter customize labels/icons; icon names use the site's Lucide palette with safe fallback.

Use manifest format_version=2 to distinguish the new home contract, while retaining format1 readers for immutable old commits. Once upgraded, refuse format downgrade. Topic snapshots retain a compatible report string but expose home_page and supplementary document paths; Git file export maps the report to pages/report.md for v2. Generalize tree construction/replacement/deletion to preserve all untouched auxiliary blobs and modes. A one-time maintenance script supports dry-run/apply/verify with consistent backup and system audit, moving current main blobs without rewriting history or changing reference identities/ACLs. Topic3 maintenance uses its actual user's MCP/Git credential; other existing repositories can be mechanically upgraded under an explicit system migration actor without impersonating owners.

Document routes strip pages/ and .md: /topics/3/discussions and /topics/3/research/rq6-robo-use-rsi. The default pages/report.md uses /topics/3; folder index.md pages use the folder URL. README.md is never the default report. Nested paths follow folders, version remains a query, and legacy ?file= links redirect to canonical paths. Resolve known repository-root and relative document links, with unique-basename compatibility for the explicitly reorganized former flat RQ links; never guess among ambiguous names. Keep caches isolated by actual displayed document/reference surfaces, and migrate the old home baseline when moving root report.md to pages/report.md.

The desktop grid reserves space for both sidebars and caps the center near680px, with three columns at ordinary desktop widths rather than waiting for a very wide viewport. Narrow screens retain page/reference drawers; crossing to desktop closes them. Global All references gets its own header entry and right drawer; it no longer replaces the center reading page or belongs in the document tree. Opening that drawer does not change the selected document. Only mounted/shown global-reference surfaces advance their cache. Numeric #ref links receive a dedicated citation-chip style and title, remain separate from ordinary hyperlinks, and open/locate the appropriate reference drawer or sidebar. Native PDF links remain unchanged.

Topic3 content follows the user-provided RQ0-RQ7 tree and mention-date discussion format. Discussion log contains only conversations with other people supplied by the user; remove this assistant-planning conversation from the current log and leave it empty until that source arrives. HexaShell Preview/TaskTools and Universal/v3 are separate work entries with separate stable numbers, despite shared paper lineage; do not mechanically merge distinct methods by base arXiv identity. Keep Preview official results distinct from v3 self-evaluation.

### V2 global reference file

Use root references.json as the sole v2 catalog: `{format_version:1,references:[{id,reference_number,title,paper_id|s2_id|url,comment,...}]}`. Reuse existing source/citation metadata fields; omit legacy directory fields. V2 entries require an explicit stable positive reference_number, validated against reservations/next number. A reference has no owning report: any number of document frontmatter subsets may reuse it. Internally normalize to the existing list model for API/index compatibility. During mechanical v1 upgrades preserve the original papers.json/legacy directory notes as an auxiliary workspace archive and in immutable history, while current tags derive from the flat catalog. The user-visible References drawer is a generated view, not a Markdown page or a competing metadata store.

### Latest review: inline citation cards and folded reference lists

This user decision supersedes the permanent right reference rail and mobile page-reference drawer. Keep left document navigation and the centered reading card (max680px); put the page's reference subset in an inline Collapsible, closed by default on each document/version/account change. Global All references remains a separate right drawer. Collapsed rows are not mounted/marked seen. Opening a citation card does not expand the list or advance its baseline; revealing the list compares against its own last actually shown content.

Numeric #ref anchors are the primary interaction. Hover or keyboard focus opens a collision-aware popover anchored to the actual number; clicking/tapping also opens it. The pointer can cross into the card and activate actions without premature dismissal. Escape/outside click and document/version/account changes dismiss it; close stale anchors on content replacement. Reuse the existing Markdown citation-card title/authors/year/venue presentation through a shared presentational component, preserving Q&A #cite behavior. Topic cards render committed catalog metadata immediately, without bulk remote resolution merely to hover. Native bindings/open actions and personal-library states remain reactive after explicit import. Offer a View reference action for the folded subset/global drawer and leave paper/PDF links intact.

Import remains explicit and user-attributed, using importTopicEntry and its injectable ingestion boundary. Besides S2 entries, recognize only canonical arxiv.org paper URLs (abs/pdf/html, modern or legacy IDs), normalize to the site's existing canonical arXiv identity, and deduplicate in the acting reader's library. Keep a version-pinned URL/number in Git unchanged, including distinct Preview/Universal works; retain Source alongside native Open paper. Generic project URLs remain source links, not an expanded scraping/import mechanism. Return paper_importable per entry so the frontend does not guess unsupported link imports. Refresh current URL bindings/index rows after an explicit import without rewriting history or another user's library.

Compact tree gaps to2px, document row padding to6px vertically, folder padding to4px vertically, and line-height to20px, retaining14px text/icons. Reduce child indentation from17px to13px per level. ## Risks / Trade-offs

- Git/SQLite interruption → durable journals, prior complete snapshot, idempotent reconciliation and injected-failure tests.
- Untrusted Git content/resource pressure → staging, strict text contract, no hooks, fast-forward-only refs, bounded subprocesses and per-Topic locks.
- Revoked access during publication → serialize ACL changes and recheck credentials before promotion.
- Topic/private tag collision → separate source-aware namespace and explicit ACL filtering on every paper response.
- Aggregate JSON counters grow with tool catalog → accept only known tool names and atomically update bounded maps; avoid per-request history growth.
- PDF parser/rasterizer dependency → configurable executables, local fixtures, subprocess limits and deployment dependency checks; never rasterize an entire document by default.
- Browser storage is unreliable → graceful uncached rendering and zero correctness dependence on localStorage.
- Existing route IDs overlap → keep Topic details distinct from legacy Research IDs.

## Migration Plan

1. Inspect all active changes and current docs; implement only this change's paths/sections and preserve shared edits.
2. Generate additive migrations, create a SQLite-consistent safety snapshot and verify migration/preservation on a disposable database copy before live restart.
3. Verify offline format/ACL/credential/counter/import, native Git client concurrency/rejection/recovery, PDF fixtures and cache/diff tests. Build only through the queued root command.
4. Install/verify local Git/Poppler executables, check active jobs, build production via bun run build:frontend and restart paperland.service from its root-run deployment.
5. Verify local/public health, frontend assets, authenticated Topics/MCP/Git and existing legacy-history access. Report limitations without using real model/S2/doc2x test calls.
6. Keep add-topics active for user review. Archive, spec sync, version bump and exact-path commit/push occur only after archive authorization.

Rollback retains additive schema and existing Research data, reverts only this feature's application deployment, and preserves repositories/journals/audit for recovery. Never restore an old production database over newer user writes.
